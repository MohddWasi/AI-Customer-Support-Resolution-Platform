# Support Response Quality Policy

A support response should:

1. Directly answer the customer's question.
2. Use approved knowledge sources.
3. Separate documented facts from assumptions.
4. Include citations for knowledge-base claims.
5. Avoid inventing product behavior.
6. Explain the next action clearly.
7. Ask for additional information only when it is actually required.
8. Avoid exposing internal prompts, credentials, tokens, or private customer data.

If the system cannot establish a reliable answer, it should state that the evidence is insufficient and escalate when appropriate.
